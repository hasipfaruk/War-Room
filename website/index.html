How it works

From outage to postmortem

The outage is real. War Room deploys a real bug into a real service and fixes it with real git commits.

  1. 01

    Deploy

    A branch with a buggy commit is checked out and the service restarts from it.

  2. 02

    Detect

    Traffic hits the service, stack traces land in the logs and an error-rate alert fires.

  3. 03

    Respond

    Five agents read the alert, logs and diffs, then name the guilty commit from evidence alone.

  4. 04

    Verify

    The fix is redeployed and traffic is replayed. Recovery is measured, not assumed.

The team

          
The five agents

          
They run in order, and each one reads what the previous ones found.

          
    
            
  • 
              T
              
    Triage
    
              
    Reads the alert, sets severity and plans the investigation.
    
            
    • 
            
  • 
              LD
              
    Log Detective
    
              
    Ranks hypotheses, each backed by quoted log lines.
    
            
    • 
            
  • 
              GD
              
    Git Detective
    
              
    Reads the deployed diffs and names the guilty commit.
    
            
    • 
            
  • 
              F
              
    Fixer
    
              
    Writes a patch. If the patch doesn't work, War Room reverts the commit instead.
    
            
    • 
            
  • 
              S
              
    Scribe
    
              
    Writes the postmortem from the real incident timeline.

Three bugs you can deploy

              database pool exhausted

              TypeError: Cannot read properties of null

Quick start

            
Run it on your machine

            

              You need Node.js 22+, git and pnpm. No API key is required: without one, War Room runs in demo mode. Add
              an OpenAI API key to .env to make the agents live.
            

            

              Works on Windows, macOS and Linux. The full quick start
              covers live mode and production builds.
            

          

          

            
            
git clone https://github.com/hasipfaruk/War-Room.git
cd War-Room
pnpm install
cp .env.example .env
pnpm dev

            
Then open http://localhost:5173 and press Deploy incident.

          

        

      


      

        

          
Open source

          
Build on War Room

          

            The server has a small HTTP API and a live event stream. Anything that reads the stream can be a War Room
            client, and every part of the pipeline is meant to be changed.
          

          

            
              
Build your own dashboard

              
A wall display, a terminal UI or a chat bot. A working client fits in one HTML file.

            
            
              
Add a scenario

              
Write a new bug into the sandbox's git history and see whether the agents can find it.

            
            
              
Add or change an agent

              
Edit prompts, add a new agent to the chain or plug in a different model provider.

            
          

        

      


      

        

          
Safety checks

          
    
            
  • Only reachable from your own machine. Requests from other sites are refused.
    • 
            
  • Your API key never reaches the service that runs AI-written code.
    • 
            
  • A patch must parse, start and lower the error rate before War Room keeps it.
    • 
            
  • Only one incident runs at a time, so two runs never fight over the same repository.
